# 집에서 따라 해 보기 — 지시문 모음

> 2026. 11. 10. 공주여성새로일하기센터 'AI 에이전트 리터러시' 실습을 Claude Code 또는 OpenAI Codex CLI로 다시 해 보는 지시문입니다.
> 실습마다 빈 폴더를 만들고, 그 폴더에서 AI를 실행한 뒤 ①부터 차례로 붙여 넣으세요. ①이 끝나면 같은 창에 ②를 붙여 넣습니다.
> 예시 입력은 새로 지어 쓴 것입니다. 내 메모로 바꿔 쓰세요. 결과(특히 숫자·날짜·공고)는 꼭 사람이 원문에서 다시 확인하세요.
> 안내 페이지: https://burn001.github.io/gongju-ai-2026/live/1110/howto/

## 공통 규칙(선택)

실습 폴더에 `CLAUDE.md`(Claude Code) 또는 `AGENTS.md`(Codex)라는 이름으로 저장해 두면 AI가 매번 읽습니다. 맨 처음 지시문 앞에 붙여 넣어도 됩니다.

```text
이 폴더에서 일할 때 지킬 것:
- 이 폴더 밖의 파일은 만들거나 고치지 않습니다.
- 무거운 조사·글쓰기는 팀원(서브에이전트)에게 나눠 맡기고, 동시에 할 수 있는 일은 동시에 합니다. 결과는 파일로 받습니다.
- 숫자·사실은 직접 확인한 값만 쓰고 출처를 답니다. 확인하지 못한 값은 지어내지 말고 "확인 필요"로 둡니다.
- 개인정보(이름·연락처·주소)는 모으지도 쓰지도 않습니다.
- 중간 말과 마지막 답은 짧고 쉬운 한국어 존댓말로 씁니다.
```

## 1. 리서치 보고서

궁금한 주제를 AI 팀이 나눠 조사해, 숫자마다 출처가 달린 개조식 보고서(한글 파일)로 만듭니다.

- 폴더: `1_보고서`
- 오늘 결과: https://burn001.github.io/gongju-ai-2026/live/1110/s1/

준비물:

- 알고 싶은 것 메모 4～6줄(오늘은 강의실 채팅으로 모았습니다 — 집에서는 아래 지시문 안의 예시 메모를 내 것으로 바꿔 쓰세요)
- 고르는 일은 사람이 합니다. ①에서 후보 3개가 나오면 마음에 드는 글자를 ②에 적어 넣으세요.
- (선택) Node.js — 한글(hwpx) 파일을 깔끔하게 만드는 공개 도구 kordoc을 씁니다. 따로 설치할 것은 없고 AI가 npx로 불러옵니다.
- (선택) KOSIS 인증키 — 실습 폴더에 kosis_key.txt로 저장해 두면 통계를 공식 API로 정확히 가져옵니다. 받는 법은 맨 위 '준비'에 있습니다.

### ① 주제 정리 — 후보 3개 고르기

```text
아래는 제가 보고서로 알고 싶은 것들을 적은 메모입니다(예시 — 내 메모로 바꿔도 됩니다).
- 우리 시에서 다시 일하려는 여성은 얼마나 될까
- 경력단절 여성이 일을 그만둔 이유
- 우리 지역에서 들을 수 있는 직업교육
- 여성 창업 지원 제도가 있는지
- 30～40대 여성 고용률이 궁금해요

비슷한 것끼리 묶어 몇 건인지 세고, 하기 어려운 것(개인정보·로그인 필요·불법·너무 큰 주제)은 이유를 한 줄 붙여 빼 주세요.
그다음 공개 통계나 정부·기관 자료로 확인할 수 있는 보고서 주제 후보 3개(A·B·C, 제목 22자 안팎)를 골라 주세요.
고르는 것은 제가 하겠습니다. 후보만 보여 주고 멈춰 주세요.
```

### ② 작업 설계 — 팀원 나누기

```text
A로 하겠습니다.(← 고른 글자로 바꾸세요)
이 주제로 작업을 설계해 주세요. 팀원(서브에이전트) 2～3명이 각각 무엇을 맡는지, 시간은 얼마나 걸리는지, 어떤 파일이 나오는지 짧게 보여 주세요.
기본 틀:
① 통계 담당 — KOSIS 국가통계포털 같은 공식 통계에서 지표 4～6개 (예: 지역별고용조사의 시군별 여성 고용률, 경력단절여성 통계). 폴더에 kosis_key.txt가 있으면 그 인증키로 KOSIS OpenAPI(https://kosis.kr/openapi/)를 직접 불러 값을 가져오고 통계표 ID를 출처에 적습니다. 키가 없으면 웹에서 찾습니다(키 내용은 화면·파일에 다시 적지 않기)
② 자료 담당 — 정부·기관·언론 자료 4～6건 (가능하면 2024～2026년 자료)
③ 작성·확인 담당 — 두 사람의 결과만 보고 초안을 쓰고, 숫자를 원자료와 대조
통계가 맞지 않는 주제면 ①을 '제도·사례 담당'으로 바꿔 주세요. 아직 조사는 하지 말고 계획만 보여 주고 멈춰 주세요.
```

### ③ 실행 — 조사하고 보고서 만들기

```text
설계한 대로 팀원들에게 나눠 조사하고, 센터장님 보고용 개조식 보고서를 만들어 주세요.
· ① 통계 담당과 ② 자료 담당은 동시에 일합니다. 결과는 work/stats.md(지표·값·단위·시점·통계표 이름·찾은 곳 주소 표)와 work/web.md(제목·기관·날짜·주소·핵심 1～2줄)에 적어 주세요. 값은 찾은 그대로 옮기고 새로 계산하지 않습니다.
· 둘이 끝나면 ③ 작성·확인 담당이 두 파일만 보고 out/보고서.md(A4 2쪽 안팎, 맨 위에 한두 문장 요약)를 씁니다. 그리고 보고서 속 숫자를 하나하나 두 파일과 대조해 work/factcheck.md(문장 속 숫자 · 근거 값 · 일치/불일치/근거 없음)에 남기고, 불일치·근거 없음은 지우거나 "확인 필요"로 고칩니다.
· 모든 숫자에 출처를 달고, 확인하지 못한 값은 지어내지 말고 "확인 필요"로 두세요.
· 마지막에 공개 도구 kordoc으로 한글(HWPX) 파일을 만들어 주세요: npx kordoc@4.24.25 generate out/보고서.md -o out/보고서.hwpx --preset 개조식 --no-toc (Node.js가 없거나 실패하면 Word 파일 out/보고서.docx로 대신 만들고 그렇게 알려 주세요).
· 끝나면 결과 파일 경로와 핵심 숫자 2～3개만 짧게 알려 주세요.
```

> 한/글이 없을 때: 한/글 프로그램이 없거나 hwpx가 잘 열리지 않으면 ③의 마지막 줄을 "Word(out/보고서.docx)로 만들어 주세요" 또는 "PDF(out/보고서.pdf)로 만들어 주세요"로 바꾸세요.

## 2. 발표 슬라이드

보고서를 센터장님 보고용 발표 슬라이드(← → 키로 넘기는 웹 화면 한 파일)로 바꿉니다. 꾸밈은 세 가지 시안을 보고 사람이 고릅니다.

- 폴더: `2_슬라이드`
- 오늘 결과: https://burn001.github.io/gongju-ai-2026/live/1110/s7/

준비물:

- 슬라이드로 바꿀 보고서 파일 1개 — 실습 1에서 만든 보고서(.md·.docx·.hwpx·.pdf 아무것이나)를 새 폴더 안 input 폴더에 복사해 두세요.
- 보고서가 없으면 공공기관 누리집에서 받은 짧은 보고서 PDF로 해도 됩니다.

### ① 디자인 시안 3종 — 같은 첫 장을 세 가지 꾸밈으로

```text
input 폴더에 있는 보고서를 센터장님 보고용 발표 슬라이드로 바꾸려 합니다.
먼저 팀원(서브에이전트) 한 명에게 보고서를 쪽(또는 절) 번호와 함께 읽게 해서 work/원문_쪽표시.md 로 정리하고,
표지 포함 9～11장의 슬라이드 내용(장 순서, 장마다 제목·핵심 문장·숫자·원문 몇 쪽)을 work/slides.md 로 써 주세요.
· 2번째 장은 '한눈에 보기' 요약, 참고자료 바로 앞 장은 결론
· 숫자는 원문 표기 그대로(계산해서 새 숫자를 만들지 않기), 원문에 없는 해석·요청은 보태지 않기
· 제목은 22자, 한 줄은 45자 안
그다음 같은 첫 장(표지)을 세 가지 꾸밈으로 만들어 나란히 보여 주세요.
· A 관제실 — 어두운 남색·청록 빛
· B 흰 종이 — 흰 바탕·파란 강조, 인쇄해도 깔끔
· C 따뜻한 크림 — 크림 바탕·둥근 카드, 안내문처럼 부드럽게
결과는 out/design_A.html · out/design_B.html · out/design_C.html 과, 셋을 나란히 보는 out/designs.html 입니다.
고르는 것은 제가 하겠습니다. 시안을 보여 주고 멈춰 주세요.
```

### ② 고른 꾸밈으로 전체 슬라이드

```text
C로 하겠습니다.(← 고른 글자로 바꾸세요)
고른 꾸밈으로 전체 슬라이드를 만들어 주세요.
· 숫자는 표 대신 그래프·카드로 크게 보여 주기
· 원문에 없는 내용은 넣지 말고, 장마다 원문 몇 쪽에서 왔는지 작게 적기
· 결과는 ← → 키로 넘기는 웹 화면 한 파일 out/slides.html (인터넷이 없어도 열리게)
· 다 만들면 다른 팀원(검수 담당)이 슬라이드의 결론·요청·숫자가 원문(work/원문_쪽표시.md)에 있는지 대조해 work/검수.md 에 적고, 고칠 곳이 있으면 고쳐 한 번 더 만들어 주세요.
```

> 한/글이 없을 때: hwpx 보고서를 AI가 읽지 못하면 한/글에서 PDF나 Word로 저장해 input 폴더에 넣으세요. 한/글이 없으면 실습 1을 Word나 PDF로 만들어 쓰면 됩니다.

## 3. 설문 자동화

물어보고 싶은 것을 모아 주제를 정하고 → 휴대폰 1분 설문 문항을 만들고 → 응답을 세어 차트가 든 결과 한 장으로 정리합니다.

- 폴더: `3_설문`
- 오늘 결과: https://burn001.github.io/gongju-ai-2026/live/1110/survey/

준비물:

- 설문으로 물어보고 싶은 것 메모 4～6줄(오늘은 강의실 채팅 — 집에서는 지시문 안 예시를 바꿔 쓰세요)
- 응답 받기: 오늘은 강의실 휴대폰 설문으로 받았습니다. 집에서는 ②에서 나온 문항을 구글 설문지(Google Forms) 같은 무료 설문 도구에 옮겨 가족·지인에게 보내고, 응답을 CSV로 내려받아 input/responses.csv 로 넣으세요.
- 응답을 받기 어려우면 ③에서 AI가 예시 응답(가상)을 만들어 연습합니다 — 결과에 '예시 응답'이라고 꼭 밝히게 되어 있습니다.

### ① 주제 고르기·설계

```text
설문을 하나 만들려고 합니다. 아래는 '설문으로 물어보고 싶은 것' 메모입니다(예시 — 내 메모로 바꿔도 됩니다).
- 다음에 어떤 교육을 듣고 싶은지
- 교육 듣기 좋은 시간대
- 아이 돌봄 때문에 못 오는 날이 있는지
- 컴퓨터 교육을 더 하면 좋겠다
- 창업 수업도 있었으면

비슷한 것끼리 묶어 가장 많이 나온 주제 하나를 고르고, 휴대폰으로 1분이면 끝나는 설문을 어떻게 만들지 보여 주세요.
· 주제(18자 안)와 고른 이유 한 문장
· 문항 5～8개, 형식별 개수(하나 고르기 · 여러 개 고르기 · 1～5점 점수 · 자유 의견 0～1개)
· 특정인·건강·재산처럼 민감한 것, 답할 수 없는 것은 빼기
설계만 보여 주고 멈춰 주세요.
```

### ② 문항 만들기

```text
설계한 대로 팀원들에게 나눠 설문 문항을 만들어 주세요.
· ① 고르는 문항 담당과 ② 점수·자유 의견 담당이 동시에 씁니다.
· 규칙: 질문은 45자 안의 쉬운 말, 한 질문에 하나만 묻기, 보기는 2～6개(서로 겹치지 않게, 필요하면 '기타'·'없음'), 이름·연락처·나이·주소는 묻지 않기
· 둘이 끝나면 ③ 다른 팀원이 어려운 말·영어, 두 가지를 한꺼번에 묻는 질문, 한쪽으로 치우친 질문, 개인정보 질문이 없는지 점검해 고쳐 주세요.
· 결과는 out/설문_문항.md — 구글 설문지에 그대로 옮겨 적기 쉬운 목록(번호 · 질문 · 형식 · 보기)으로 만들어 주세요.
```

### ③ 응답 분석 → 결과 한 장

```text
input/responses.csv 는 이 설문의 응답입니다(설문 도구에서 내려받음).
응답 파일이 없거나 3건 미만이면, 이 설문 문항으로 예시 응답 14건(가상)을 만들어 input/responses.csv 로 저장하고 결과마다 "예시 응답"이라고 꼭 밝혀 주세요.

응답을 분석해 결과 한 장 화면을 만들어 주세요.
· 숫자는 먼저 프로그램으로 센 값(명수·퍼센트·평균)만 work/stats.json 에 저장하고, 그 값만 씁니다. 계산해서 새 숫자를 만들지 않습니다.
· 팀원 세 명이 동시에 work/stats.json 만 보고 맡습니다: ① 해석(한 문장 결론 + 3줄) ② 자유 의견 묶기(2～4묶음, 대표 글은 30자 안으로 줄여서) ③ 센터가 해 볼 일 2가지(결과 숫자에 근거)
· 결과는 차트가 든 한 장 화면 out/survey_result.html (인터넷이 없어도 열리게). 개인을 알아볼 수 있는 내용은 빼 주세요.
```

## 4. 모션그래픽

하고 싶은 말을 모아 25～30초짜리 홍보 영상 장면을 구성하고, 브라우저에서 반복 재생되는 움직이는 화면(HTML) 한 파일로 만듭니다.

- 폴더: `4_모션그래픽`
- 오늘 결과: https://burn001.github.io/gongju-ai-2026/live/1110/motion/

준비물:

- 홍보 문구·하고 싶은 말 3～6줄(오늘은 강의실 채팅 — 집에서는 지시문 안 예시를 바꿔 쓰세요)
- 홍보할 기관의 사실 몇 줄 — 반드시 그 기관 누리집에서 직접 확인한 것만 적으세요. 지시문 안 [기관 사실]은 형식을 보여 주는 예시입니다.

### ① 장면 구성

```text
홍보 영상(25～30초)을 브라우저에서 반복 재생되는 움직이는 화면으로 만들려고 합니다.
아래 [하고 싶은 말]과 [기관 사실]을 읽고 장면 5～6개를 구성해 주세요.

[하고 싶은 말](예시)
- 경력은 멈춰도 꿈은 멈추지 않아요
```
