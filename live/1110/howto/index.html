보고서 실습용 도구(선택)

없어도 실습은 됩니다. 있으면 리서치 보고서의 통계와 한글 파일이 강의 때처럼 정확해집니다. 스킬·플러그인을 따로 설치할 필요는 없습니다.

  • Node.js(nodejs.org, LTS) — 설치만 해 두면 AI가 공개 도구 kordoc을 npx로 불러 hwpx를 만듭니다. 스킬·플러그인 설치는 필요 없습니다.
  • KOSIS 통계 도구 korean-stats(공개 오픈소스 chrisryugj/korean-stats-mcp) — 내 KOSIS 인증키로 내 PC에서 돌립니다. AI가 "공주시 여성 고용률"처럼 말로 KOSIS 통계를 통계표 ID와 함께 가져옵니다.
    1. KOSIS 공유서비스(OpenAPI)에서 회원가입 → 활용신청 → 인증키 발급(무료).
    2. 실습 폴더에서 아래 한 줄의 내키를 발급받은 키로 바꿔 실행하고, AI를 다시 시작합니다(Node.js 필요).
    claude mcp add korean-stats -e KOSIS_API_KEY=내키 -- cmd /c npx -y korean-stats-mcp claude mcp add korean-stats -e KOSIS_API_KEY=내키 -- npx -y korean-stats-mcp codex mcp add korean-stats --env KOSIS_API_KEY=내키 -- npx -y korean-stats-mcp (차례로 Claude Code Windows · Claude Code Mac · Codex.) Claude Code에서는 /mcp 로 연결됐는지 볼 수 있습니다. 키는 내 PC 설정에만 저장되니 남에게 보여 주거나 인터넷에 올리지 마세요.
실습할 때마다
  1. 문서 폴더에 AI실습 폴더를 만들고, 그 안에 실습마다 빈 폴더를 하나씩 만듭니다(예: 1_보고서).
  2. 그 폴더를 파일 탐색기에서 열고 빈 곳을 오른쪽 클릭 → 터미널에서 열기(Mac은 폴더를 터미널 아이콘에 끌어다 놓기).
  3. claude 또는 codex 를 입력해 실행하고, 아래 지시문을 복사해 붙여 넣습니다. AI는 이 폴더 안에서만 일합니다.
  4. AI가 파일을 만들거나 명령을 실행하려 하면 허락을 묻습니다. 무엇을 하려는지 읽어 보고 허락하세요.
  5. 단계가 여러 개면 ①이 끝나 AI가 멈춘 뒤 같은 창에 ②를 붙여 넣습니다. 창을 닫았다면 같은 폴더에서 claude --continue(Codex는 codex resume)로 이어 갑니다.
  6. 결과는 폴더 안 out 폴더에 생깁니다. html 파일은 두 번 눌러 브라우저로 엽니다.
공통 규칙(선택) — 실습 폴더에 저장해 두면 AI가 매번 읽습니다

Claude Code는 CLAUDE.md, Codex는 AGENTS.md 라는 이름의 파일로 실습 폴더에 저장하세요. 첫 지시문 앞에 붙여 넣어도 됩니다.

공통 규칙
이 폴더에서 일할 때 지킬 것:
- 이 폴더 밖의 파일은 만들거나 고치지 않습니다.
- 무거운 조사·글쓰기는 팀원(서브에이전트)에게 나눠 맡기고, 동시에 할 수 있는 일은 동시에 합니다. 결과는 파일로 받습니다.
- 숫자·사실은 직접 확인한 값만 쓰고 출처를 답니다. 확인하지 못한 값은 지어내지 말고 "확인 필요"로 둡니다.
- 개인정보(이름·연락처·주소)는 모으지도 쓰지도 않습니다.
- 중간 말과 마지막 답은 짧고 쉬운 한국어 존댓말로 씁니다.
꼭 지켜 주세요
  • 요금 — 두 도구 모두 유료 요금제나 사용량 요금이 듭니다. 오래 돌리거나 많이 시키면 사용 한도가 빨리 찹니다. 실습 하나씩 짧게 해 보세요.
  • 개인정보 — 내가 넣은 글과 파일은 AI 회사 서버로 보내집니다. 주민등록번호·계좌·비밀번호, 남의 이름·연락처는 넣지 마세요.
  • 확인은 사람이 — AI 결과는 초안입니다. 숫자·날짜·공고·시설 정보는 원문을 열어 다시 확인하고, 고르고 정하는 일은 사람이 하세요.
  • 사이트 예의 — 남의 사이트를 짧은 시간에 많이 열게 하지 마세요. 로그인이 필요한 곳은 맡기지 않습니다.

오늘 강의실에서는 채팅·투표·휴대폰 설문으로 입력을 모으고, 미리 만들어 둔 도구로 시간을 줄였습니다. 아래 지시문은 그런 장치 없이 혼자 돌아가도록 고쳐 쓴 것이라, 결과 모양은 오늘과 조금 다를 수 있습니다. 팀원(서브에이전트)을 나눠 쓰는 방식은 Claude Code 기준입니다.

① 주제 정리 — 후보 3개 고르기
아래는 제가 보고서로 알고 싶은 것들을 적은 메모입니다(예시 — 내 메모로 바꿔도 됩니다).
- 우리 시에서 다시 일하려는 여성은 얼마나 될까
- 경력단절 여성이 일을 그만둔 이유
- 우리 지역에서 들을 수 있는 직업교육
- 여성 창업 지원 제도가 있는지
- 30～40대 여성 고용률이 궁금해요

비슷한 것끼리 묶어 몇 건인지 세고, 하기 어려운 것(개인정보·로그인 필요·불법·너무 큰 주제)은 이유를 한 줄 붙여 빼 주세요.
그다음 공개 통계나 정부·기관 자료로 확인할 수 있는 보고서 주제 후보 3개(A·B·C, 제목 22자 안팎)를 골라 주세요.
고르는 것은 제가 하겠습니다. 후보만 보여 주고 멈춰 주세요.
② 작업 설계 — 팀원 나누기
A로 하겠습니다.(← 고른 글자로 바꾸세요)
이 주제로 작업을 설계해 주세요. 팀원(서브에이전트) 2～3명이 각각 무엇을 맡는지, 시간은 얼마나 걸리는지, 어떤 파일이 나오는지 짧게 보여 주세요.
기본 틀:
① 통계 담당 — KOSIS 국가통계포털 같은 공식 통계에서 지표 4～6개 (예: 지역별고용조사의 시군별 여성 고용률, 경력단절여성 통계). korean-stats(KOSIS) 도구가 연결돼 있으면 그 도구로 값을 가져오고 통계표 ID를 출처에 적습니다. 도구가 없으면 웹에서 찾습니다
② 자료 담당 — 정부·기관·언론 자료 4～6건 (가능하면 2024～2026년 자료)
③ 작성·확인 담당 — 두 사람의 결과만 보고 초안을 쓰고, 숫자를 원자료와 대조
통계가 맞지 않는 주제면 ①을 '제도·사례 담당'으로 바꿔 주세요. 아직 조사는 하지 말고 계획만 보여 주고 멈춰 주세요.
③ 실행 — 조사하고 보고서 만들기
설계한 대로 팀원들에게 나눠 조사하고, 센터장님 보고용 개조식 보고서를 만들어 주세요.
· ① 통계 담당과 ② 자료 담당은 동시에 일합니다. 결과는 work/stats.md(지표·값·단위·시점·통계표 이름·찾은 곳 주소 표)와 work/web.md(제목·기관·날짜·주소·핵심 1～2줄)에 적어 주세요. 값은 찾은 그대로 옮기고 새로 계산하지 않습니다.
· 둘이 끝나면 ③ 작성·확인 담당이 두 파일만 보고 out/보고서.md(A4 2쪽 안팎, 맨 위에 한두 문장 요약)를 씁니다. 그리고 보고서 속 숫자를 하나하나 두 파일과 대조해 work/factcheck.md(문장 속 숫자 · 근거 값 · 일치/불일치/근거 없음)에 남기고, 불일치·근거 없음은 지우거나 "확인 필요"로 고칩니다.
· 모든 숫자에 출처를 달고, 확인하지 못한 값은 지어내지 말고 "확인 필요"로 두세요.
· 마지막에 공개 도구 kordoc으로 한글(HWPX) 파일을 만들어 주세요: npx kordoc@4.24.25 generate out/보고서.md -o out/보고서.hwpx --preset 개조식 --no-toc (Node.js가 없거나 실패하면 Word 파일 out/보고서.docx로 대신 만들고 그렇게 알려 주세요).
· 끝나면 결과 파일 경로와 핵심 숫자 2～3개만 짧게 알려 주세요.
한/글이 없을 때 한/글 프로그램이 없거나 hwpx가 잘 열리지 않으면 ③의 마지막 줄을 "Word(out/보고서.docx)로 만들어 주세요" 또는 "PDF(out/보고서.pdf)로 만들어 주세요"로 바꾸세요.
막히면
  • 숫자가 거의 "확인 필요"로 나오면: 통계 누리집 화면은 AI가 자동으로 읽기 어려울 때가 있습니다. 맨 위 '준비'의 korean-stats 도구를 등록하고 AI를 다시 시작하면 가장 확실합니다(Claude Code는 /mcp 로 연결 확인). 도구 없이 하려면 KOSIS에서 표를 직접 내려받아(엑셀·CSV) 폴더에 넣고 "input 폴더의 통계표에서 숫자를 찾아 주세요"라고 덧붙이세요.
  • hwpx 파일이 한/글에서 열리지 않으면 Word나 PDF로 바꿔 달라고 하세요(위 대안).

· 공고마다 제목·회사·근무지 주소(아는 만큼)·직무·고용형태·급여·근무시간·마감일·원문 주소·출처를 work/jobs_raw.json 에 모읍니다.
· 담당자 휴대전화·이메일 같은 개인 연락처는 절대 모으지 않고, 지어내지 않습니다.
끝나면 출처별 건수와 뺀 이유만 짧게 알려 주고 멈춰 주세요.
② 정리·점수
② 이어서 같은 공고는 하나로 묶고, 직종을 나누고, 경력단절여성에게 맞는지 점수를 매겨 주세요.
· 같은 회사 + 같은 직무 + 같은 근무지면 같은 공고입니다(같은 매장이라도 근무 시간대·요일·직무가 다르면 다른 공고).
· 마감이 지난 공고와 ○○시 밖 근무는 뺍니다.
· 점수 기준을 먼저 짧게 정해 work/점수기준.md 에 적고(예: 경력 무관·초보 가능, 낮 시간·시간제, 자격 부담, 교육 지원 여부), 공고마다 '적합 / 조건부 / 부적합'과 이유 한 줄을 붙입니다.
· 주소를 지도 좌표로 바꿉니다(무료 지도 검색은 1초에 한 번만). 정확한 주소가 없으면 읍·면·동 중심에 두고 '위치 근사'로 표시합니다.
· 결과는 work/jobs.json. 끝나면 건수만 짧게 알려 주고 멈춰 주세요.
③ 지도 ④ 검수
③ 지도 대시보드 out/jobs_map.html 을 만들어 주세요.
· 지도 위에 공고를 표시하고 직종·적합도로 걸러 볼 수 있게, 공고를 누르면 원문 주소가 나오게
· 배경 지도는 Esri 거리 지도를 기본으로 하고, 불러오지 못하면 OpenStreetMap으로 넘어가게
④ 그다음 다른 AI(검수 담당)가 숫자를 다시 세고, 공고 5건을 골라 원문을 열어 제목·회사·근무지·마감일이 jobs.json 과 맞는지 대조해 work/검수.md 에 적게 해 주세요. 열리지 않으면 '확인 불가'로 적습니다.
마지막에 총 공고 수, 적합 비율, 가장 많은 직종, 검수 결과를 5줄 안으로 알려 주세요.
